osu!stable / osu!lazer Taiko Spinner Appearance Timing

This page is a technical reference for the Modding Helper documentation.

osu!taiko spinners (Swells / balloons) are displayed differently in osu!stable and osu!lazer. In particular, stable has a legacy behaviour that calculates a warning lead-in from the first timing point in the beatmap. If that first point is inherited, the calculation falls back to a different path than normal. This page separately explains when the object enters the playfield, when its warning appears, when its main body appears, and when input becomes valid.

osu!lazer
Uses the spinner's local speed
The spinner enters using the normal scroll calculation and moves to the top-level layer 100 ms before its start time.
osu!stable
Also uses the first timing point
In addition to each spinner's lifetime, stable calculates a shared warning lead-in from the first timing point.
stable-specific
Different result if green comes first
The initial red timing-point index still refers to the first inherited point, causing the velocity fallback to be used.

What “appearance” means: this page treats entering from the right, showing the spinner warning, showing the main spinner body, and accepting input as separate events. A single appearance timestamp cannot describe both clients accurately.

3. osu!lazer calculation

lazer 1Taiko time range

lazer clamps the Taiko playfield's aspect ratio between 5:4 and 16:9, then calculates a time range that reproduces stable's scrolling distance.

A' = clamp(A, 5 / 4, 16 / 9)

T = ((480 × A' - 160) / 100 × 1000) / 1.4

The constant 480 is stable's gameplay-field height, 160 is the hit position, and 1.4 is Taiko's internal conversion multiplier. The implementation and its derivation are documented in TaikoPlayfieldAdjustmentContainer.ComputeTimeRange().

lazer 2Velocity multiplier at the spinner

lazer combines timing points and effect points into MultiplierControlPoint instances.

M(S) = SM × SV(S) × 1000 / B(S)

In the official source, this is implemented as Velocity × EffectPoint.ScrollSpeed × BaseBeatLength / TimingPoint.BeatLength. See MultiplierControlPoint.Multiplier.

lazer 3When the spinner begins entering the playfield

Taiko uses the Overlapping visualisation method, in which each object uses the velocity active at its own start time.

D_lazer = ((W + o) / W) × T / M(S)

laneAppearanceTime = S - D_lazer
  • (W + o) / W adds enough padding for the complete object, including its radius, to enter from beyond the screen.
  • The display start depends on B(S) and SV(S) at the spinner; the first timing point in the beatmap receives no special spinner-specific treatment.
  • The position is equivalent to (S - currentTime) / T × M(S) × W.

The display-start calculation is in GetDisplayStartTime(), while the position calculation is in PositionAt().

lazer 4Top-level layer switch 100 ms before the start

ringAppearOffset = 100
proxyTime = S - ringAppearOffset

DrawableSwell defines ring_appear_offset = 100 and calls ProxyContent() when the current time reaches S - 100. This does not create the spinner for the first time. It moves the content from the normal hit-object layer to an unmasked top-level layer.

if currentTime >= S - 100:
    ProxyContent()
else:
    UnproxyContent()

X = max(0, X)

After the start time, X = max(0, X) prevents the spinner from moving past the hit target. Input uses a separate condition and is ignored while currentTime < S.

Key lazer behaviour: the normal Taiko scrolling formula determines when the spinner enters from the right, the content switches to the top-level layer 100 ms before the start, and input becomes valid at the start time.

4. osu!stable calculation

stable 1Taiko's internal SliderMultiplier

SM_taiko = SM × 1.4

When stable initialises its Taiko HitObjectManager, it multiplies the beatmap's SliderMultiplier by 1.4. lazer retains the same compatibility constant as VELOCITY_MULTIPLIER.

stable 2Effective beat length from uninherited and inherited points

Within the normal range, the effective beat length is the uninherited beat length divided by SV.

E(t) = B(t) / SV(t)

Expressed directly in terms of stable's raw inherited beat-length value, the calculation is:

q(G) = clamp(-G(t), 10, 10000) / 100

if a valid inherited point occurs after the selected uninherited point:
    E(t) = B(t) × q(G)
else:
    E(t) = B(t)

For the usual G = -100 / SV, this gives q(G) = 1 / SV.

stable 3Per-object display lead-in

V(t) = 100000 × SM_taiko / E(t)

L(t) = trunc(600 / V(t) / 0.6000000238418579 × 1000)
     ≒ trunc(1000000 / V(t))
     ≒ trunc(10 × E(t) / SM_taiko)

The spinner becomes eligible for drawing at approximately:

objectLifetimeStart = S - L(S)

L(S) uses the uninherited and inherited timing points active at the spinner. It represents the travel time from outside the playfield to the hit position and is also used for normal notes and drum rolls.

stable 4Warning and main-body display

In stable's Swell class, the warning sprite and main spinner body have separate transformations.

Warning:
    fadeStart    = S - P
    fadeComplete = S - trunc(0.6 × P)

Main body:
    fadeStart    = S - 1
    fadeComplete = S + 200

Input:
    valid from S

The warning sprite's fade uses the shared preempt value P, but the hit object itself is not drawn before S - L(S). The earliest time at which the warning can actually become visible is therefore approximately:

actualWarningStart = S - min(P, L(S))

5. stable's first timing-point dependency

stable legacyShared preempt calculation

When stable's Taiko HitObjectManager loads the beatmap, it obtains the velocity at the first timing point's timestamp and calculates a shared preempt value once.

t_first = timestamp of the first timing point

P = trunc(min(5000,
              600 / V(t_first)
              / 0.6000000238418579
              × 1000))

  ≒ trunc(min(5000,
              10 × E(t_first) / SM_taiko))

This value is used by stable's spinner warning and related display logic. As a result, changing the first uninherited timing point can change the warning lead-in even if all timing around the spinner itself remains unchanged.

stable bugWhen the first point is inherited

In the timing-point lookup, both the latest uninherited index and latest inherited index are initialised to 0.

redIndex = 0
greenIndex = 0

for point in TimingPoints:
    if point.time <= queryTime:
        if point is uninherited:
            redIndex = point.index
        else:
            greenIndex = point.index

If the first point is inherited, no uninherited point has been found, yet redIndex = 0 still causes that first inherited point to be read through the uninherited-point path. The effective beat length becomes negative and the velocity calculation enters its fallback path.

V_fallback = 100 × SM_taiko

P_greenFirst
    = trunc(min(5000, 1000000 / V_fallback))
    = trunc(min(5000, 10000 / SM_taiko))
Interpretation: stable is not correctly applying the first inherited point's SV here. Instead, the uninherited lookup's initial index still refers to that inherited point, which sends the calculation into the fallback path. This is best understood as a stable-specific bug preserved as legacy behaviour rather than an intentional rule.

8. Implementation proposal for the Modding Helper preview

The current game-style Test view moves the spinner from the right at the same speed as other notes, then holds it at the hit target after its start. Accurately matching the clients requires the individual display stages to be modelled separately.

lazer-compatible
Scrolling plus a 100 ms layer switch
  1. Scroll the spinner using its local M(S).
  2. Switch to the top-level display at S - 100.
  3. Reach the hit target at S and remain there.
stable-compatible
Separate warning and main body
  1. Calculate P from a timing-point list that preserves original ordering.
  2. Calculate L(S) from the timing active at the spinner.
  3. Show the warning from S - min(P, L(S)).
  4. Fade the main body from S - 1 through S + 200.
Implementation note: reproducing stable's inherited-first bug and the ordering of uninherited and inherited points at the same timestamp requires one unified timing-point list that preserves file order and the inherited flag. Separately parsed red and green arrays are not sufficient.
Summary
In lazer, the normal Taiko scrolling formula determines when a spinner enters the screen, and its content moves to the top-level layer 100 ms before the start.
In stable, the per-spinner display lifetime L(S) is combined with a shared preempt value P calculated from the first timing point in the beatmap.
If the first point is inherited, the initial uninherited index still refers to that point, so the fallback velocity is used instead of the normal SV calculation.
An accurate preview should model playfield entry, warning display, main-body display, and input start separately, with distinct stable and lazer profiles.
