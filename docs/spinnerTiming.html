osu!stable / osu!lazer Taikoスピナー出現時間の計算

このページは Modding Helper 説明書 の技術資料です。

osu!taikoのスピナー（Swell／風船）は、osu!stableとosu!lazerで表示処理が異なります。 特にstableは、譜面の最初のタイミングポイントから予告時間を計算するlegacy挙動を持ち、 最初のポイントが緑線の場合には通常と異なるフォールバックへ入ります。 このページでは、画面右側から見え始める時刻、予告表示、本体表示、入力開始を分けて整理します。

osu!lazer
スピナー位置の速度を使用
通常のスクロール式で画面へ入り、開始100 ms前に上位レイヤーへ切り替わります。
osu!stable
先頭Timing Pointも使用
スピナー自身の表示寿命に加え、譜面先頭から共通の予告時間を計算します。
stable固有
最初が緑線なら別計算
赤線検索の初期インデックスが先頭の緑線を参照し、速度のフォールバックが使われます。

3. osu!lazerの計算

lazer 1TaikoのTimeRange

lazerはTaikoプレイフィールドのアスペクト比を5:4から16:9へ制限し、stableのスクロール距離を再現するTimeRangeを求めます。

A' = clamp(A, 5 / 4, 16 / 9)

T = ((480 × A' - 160) / 100 × 1000) / 1.4

定数480はstableのゲームフィールド高さ、160は判定位置、1.4はTaiko変換時の内部速度倍率です。実装と由来はTaikoPlayfieldAdjustmentContainer.ComputeTimeRange()に記載されています。

lazer 2スピナー位置の速度倍率

lazerはタイミングポイントとEffect Pointを統合したMultiplierControlPointを作ります。

M(S) = SM × SV(S) × 1000 / B(S)

公式コード上では、Velocity × EffectPoint.ScrollSpeed × BaseBeatLength / TimingPoint.BeatLengthとして実装されています。MultiplierControlPoint.Multiplier

lazer 3レーンへ入り始める時刻

Taikoは、各オブジェクトが自分の開始時刻で有効な速度を持つOverlapping方式です。

D_lazer = ((W + o) / W) × T / M(S)

laneAppearanceTime = S - D_lazer
  • (W + o) / Wは、円の半径などを含め、オブジェクト全体が画面外から入るための余白です。
  • 表示開始時刻はスピナー位置のB(S)とSV(S)で決まり、譜面先頭のTiming Pointを特別扱いしません。
  • 位置は(S - currentTime) / T × M(S) × Wに相当する式で更新されます。

表示開始式はGetDisplayStartTime()、位置計算は同ファイルのPositionAt()で確認できます。

lazer 4100 ms前の上位レイヤー切替

ringAppearOffset = 100
proxyTime = S - ringAppearOffset

DrawableSwellはring_appear_offset = 100を定義し、現在時刻がS - 100以上になるとProxyContent()を呼びます。これはスピナーを初めて生成する処理ではなく、通常のHitObjectレイヤーから、マスクされない上位レイヤーへ内容を移す処理です。

if currentTime >= S - 100:
    ProxyContent()
else:
    UnproxyContent()

X = max(0, X)

開始後はX = max(0, X)により判定位置より左へ進みません。入力受付は別条件で、currentTime < Sの入力は無視されます。

lazerの要点：右側から見え始める時刻は通常のスクロール式、上位レイヤーへの切替は開始100 ms前、入力受付は開始時刻からです。

4. osu!stableの計算

stable 1Taiko内部のSliderMultiplier

SM_taiko = SM × 1.4

stableはTaiko用HitObjectManagerの初期化時に、譜面のSliderMultiplierへ1.4を掛けます。lazer側にも同じ互換定数がVELOCITY_MULTIPLIERとして残っています。

stable 2赤線と緑線から有効beat lengthを求める

通常範囲では、有効beat lengthは赤線のbeat lengthをSVで割った値です。

E(t) = B(t) / SV(t)

生の緑線値を使ったstableの処理をそのまま書くと、次の式です。

q(G) = clamp(-G(t), 10, 10000) / 100

if 有効な緑線が赤線より後にある:
    E(t) = B(t) × q(G)
else:
    E(t) = B(t)

通常のG = -100 / SVではq(G) = 1 / SVとなります。

stable 3オブジェクトごとの表示先行時間

V(t) = 100000 × SM_taiko / E(t)

L(t) = trunc(600 / V(t) / 0.6000000238418579 × 1000)
     ≒ trunc(1000000 / V(t))
     ≒ trunc(10 × E(t) / SM_taiko)

スピナー自身が描画対象になる開始時刻は、概ね次です。

objectLifetimeStart = S - L(S)

L(S)はスピナー位置の赤線・緑線から求めます。これは通常ノーツや連打にも使われる、画面外から判定位置までの移動時間に相当します。

stable 4予告表示と本体表示

stableのSwellクラスでは、予告用スプライトとスピナー本体が異なる変換を持ちます。

予告表示:
    fadeStart    = S - P
    fadeComplete = S - trunc(0.6 × P)

本体表示:
    fadeStart    = S - 1
    fadeComplete = S + 200

入力受付:
    S から

予告用スプライトのフェードは共通プリエンプトPを使いますが、HitObject自体はS - L(S)より前には描画対象になりません。したがって、予告が実際に見え始める最早時刻は概ね次です。

actualWarningStart = S - min(P, L(S))

5. stableの先頭Timing Point依存

stable legacy共通プリエンプトの計算

stableのTaiko HitObjectManagerは、譜面を読み込む際に最初のタイミングポイントの時刻で速度を取得し、共通プリエンプトを一度だけ計算します。

t_first = 最初のTiming Pointの時刻

P = trunc(min(5000,
              600 / V(t_first)
              / 0.6000000238418579
              × 1000))

  ≒ trunc(min(5000,
              10 × E(t_first) / SM_taiko))

この値が、stableのスピナー予告表示などに使われます。そのため、スピナー位置のタイミングが同じでも、譜面先頭の赤線を変えると予告時間が変わる場合があります。

stable bug最初のポイントが緑線の場合

タイミングポイント検索では、最新の赤線を示すインデックスと最新の緑線を示すインデックスが、どちらも0で初期化されています。

redIndex = 0
greenIndex = 0

for point in TimingPoints:
    if point.time <= queryTime:
        if point is red:
            redIndex = point.index
        else:
            greenIndex = point.index

先頭が緑線の場合、赤線が一度も見つかっていないにもかかわらず、redIndex = 0のまま先頭の緑線を赤線側からも参照します。結果の有効beat lengthは負値となり、速度計算がフォールバックへ入ります。

V_fallback = 100 × SM_taiko

P_greenFirst
    = trunc(min(5000, 1000000 / V_fallback))
    = trunc(min(5000, 10000 / SM_taiko))
判断：「最初の緑線を基準に正しくSVを計算している」のではなく、赤線検索の初期値が先頭要素を指したままになることでフォールバックへ入ります。意図的な仕様より、stable固有のバグが互換挙動として残ったものと考えるのが自然です。

6. 計算例

共通条件 
SliderMultiplier = 1.4
SM_taiko = 1.4 × 1.4 = 1.96

最初が500 msの赤線

P = trunc(min(5000,
              10 × 500 / 1.96))
  = trunc(2551.0204...)
  = 2551 ms

最初が緑線

P = trunc(min(5000,
              10000 / 1.96))
  = trunc(min(5000, 5102.0408...))
  = 5000 ms

スピナー位置が500 ms、SV 2.0

E(S) = 500 / 2 = 250

L(S) = trunc(10 × 250 / 1.96)
     = 1275 ms

先頭が緑線でP = 5000になっていても、オブジェクト自体はS - 1275まで描画対象になりません。

actualWarningStart
    = S - min(5000, 1275)
    = S - 1275 ms
先頭が500 ms赤線2551 ms前
先頭が緑線5000 ms前
SV 2.0での実表示制限1275 ms前

8. Modding Helperプレビューへの実装方針

現在のゲーム画面風Testでは、スピナーを通常ノーツと同じ速度で右から移動させ、開始後は判定枠に留めています。各クライアントを正確に再現するには、表示段階を個別に扱う必要があります。

lazer互換
スクロール＋100 ms前のレイヤー切替
  1. スピナー位置のM(S)を使用してスクロールさせる。
  2. S - 100で上位レイヤー表示へ切り替える。
  3. Sで判定枠へ到達し、その位置に留める。
stable互換
予告表示と本体表示を分離
  1. ファイル上の順序を保ったTiming Point一覧からPを計算する。
  2. スピナー位置で有効なタイミングからL(S)を計算する。
  3. S - min(P, L(S))から予告表示を開始する。
  4. S - 1からS + 200にかけて本体をフェードインする。
実装上の注意：stableの「最初が緑線」のバグや、同時刻にある赤線・緑線の順序を再現するには、ファイル上の順序とinheritedフラグを保持した単一のTiming Point一覧が必要です。赤線と緑線を別々の配列へ分けて解析するだけでは足りません。
まとめ
lazerでは、スピナーが画面へ入る時刻は通常のTaikoスクロール式で決まり、開始100 ms前に内容を上位レイヤーへ移します。
stableでは、スピナー自身のタイミングから求める表示寿命L(S)に加え、譜面先頭のTiming Pointから共通プリエンプトPを計算します。
最初が緑線の場合は赤線検索の初期インデックスが先頭の緑線を参照するため、通常のSV計算ではなくフォールバック速度となります。
プレビューで正確に再現する場合は、「レーンへの出現」「予告表示」「本体表示」「入力開始」を分離し、stable / lazerを別プロファイルとして扱う必要があります。
